# Historical processing research: rexafs 0.1.3

These September 7–8, 2026 measurements used an Apple M4 with 32 GiB RAM,
optimized Rust release builds and XrayLarch 2026.3.1. They are retained research
results, **not a benchmark of current main**. The [aggregate data](2026-09-07-08-summary.json)
records the original source paths and stash commit. The full original logs,
profiles and prototype sources are preserved in a separate local archive;
they are not required to install or build rexafs.

## Loaded-spectrum processing

The timed boundary was normalization → AUTOBK → output FFT, after arrays,
spectrum objects and parameters were prepared. File loading, input copying,
FEFF execution and structural fitting were excluded. A repeating Cu/Ni/Ru
fixture mixture was processed in chunks of 1,000 with fresh solves and FFTs;
this was not one million distinct scans held in memory together.

| Library | Workers | Spectra | Measured processing time |
|---|---:|---:|---:|
| rexafs 0.1.3 | 10 Rayon threads | 1,000,000 | 26.972 s |
| XrayLarch 2026.3.1 | 1 thread | 10,000 | 45.904 s |

The throughput ratio for those different worker counts was 170.2×. Larch's
76.5-minute million-spectrum time was extrapolated; it was not measured.
The rexafs result was one cumulative run, not repeated million-spectrum trials.
Repeated geometry favors reusable preparation, so heterogeneous data can behave
differently. Background OS activity was not eliminated.

The maximum chi(k) relative L2 difference against Larch was 0.001642% over
2–12 Å⁻¹ for the measured fixtures. The historical Fourier-window convention
also differed in R-space; chi(k) agreement is not whole-pipeline equivalence.
See the current [FFT compatibility record](../fft-grid-compatibility.md) when
choosing the window domain. A separate instrumented audit recorded 465.3 MiB
peak combined sampled RSS; it was not the timing run.

## Resampling and cached-SVD prototypes

The follow-up compared 0.1.3-based prototypes using fifteen randomized rounds
per variant. Each single-thread round processed 1,000 prepared spectra; each
ten-thread round processed 10,000 in chunks. Values below are median µs/spectrum.

| Threads | Cubic baseline | Linear interpolation | Cached SVD + cubic |
|---|---:|---:|---:|
| 1 | 107.94 | 98.17 | 93.94 |
| 10 | 26.08 | 25.35 | 22.80 |

Cached SVD with cubic interpolation gave a 1.149× single-thread throughput
ratio, with paired-bootstrap 95% interval 1.119–1.181. Its ten-thread interval
was 0.928–1.218, so a parallel improvement was not established by this run.
Linear interpolation changed the numerical outputs and exceeded the study's
chi compatibility threshold on the measured scans. These results motivate
preparation reuse while retaining cubic interpolation; they do not justify
changing the production interpolation model or promise a particular speedup.

The [normalization experiment](../../experiments/normalization_stability/README.md)
is retained separately with runnable source and concise results. Historical UX
plans, release logs and superseded assistant documentation were not folded into
the current user guides.
